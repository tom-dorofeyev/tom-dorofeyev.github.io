I built an open-source library a while ago and made the classic developer mistake:

**I never told anyone about it.**

It's called [**Sagalicious**](https://github.com/tom-dorofeyev/sagalicious). It's a small TypeScript library for workflows where several operations need to succeed together, and earlier actions need compensation if something fails.

## The payment went through. Shipping failed.

Take an order workflow:

1. Create the order.
2. Charge the payment.
3. Reserve inventory.
4. Ship the order.

If shipping fails, the customer has still been charged and the inventory is still reserved. Stopping the workflow leaves those earlier actions in place.

A saga pairs those steps with compensating actions: release the inventory, refund the payment, and cancel the order. An orchestrator runs the workflow and triggers compensation on failure.

You write the actions and their compensations. Sagalicious coordinates when they run.

## Pair an action with its compensation

Install the package in your Node.js project:

```sh
npm install sagalicious
```

For an order that already exists, payment, inventory, and shipping each need different data. Define a command DTO for each action:

```typescript
import { createSaga, type Command } from 'sagalicious';
import { payments, inventory, shipping } from './order-services';

interface PaymentCommand extends Command {
  type: 'payment';
  data: {
    paymentId: string;
    customerId: string;
    amountCents: number;
    currency: string;
  };
}

interface InventoryCommand extends Command {
  type: 'inventory';
  data: {
    reservationId: string;
    items: { sku: string; quantity: number }[];
  };
}

interface ShippingCommand extends Command {
  type: 'shipping';
  data: {
    shipmentId: string;
    orderId: string;
    addressId: string;
  };
}
```

The `type` selects a handler. The `data` property is our DTO design, not a required Sagalicious field: the library passes the command object to the handler as-is.

Now register the handlers with the [functional API](https://github.com/tom-dorofeyev/sagalicious#quick-start):

```typescript
const checkout = createSaga()
  .handler<PaymentCommand>('payment', {
    execute: async ({ data }) => {
      await payments.charge(data);
    },
    rollback: async ({ data }) => {
      await payments.refundIfCharged(data.paymentId);
    },
  })
  .handler<InventoryCommand>('inventory', {
    execute: async ({ data }) => {
      await inventory.reserve(data);
    },
    rollback: async ({ data }) => {
      await inventory.releaseIfReserved(data.reservationId);
    },
  })
  .handler<ShippingCommand>('shipping', {
    execute: async ({ data }) => {
      await shipping.createShipment(data);
    },
    rollback: async ({ data }) => {
      await shipping.cancelIfCreated(data.shipmentId);
    },
  })
  .build();
```

Each handler receives its own typed payload. Payment sees the amount and customer; inventory sees the items; shipping sees the order and delivery address reference.

The imported services are illustrative application code you supply. They keep a record under each application-generated ID, including any provider reference needed for compensation. For example, `payments.charge` stores the provider's charge reference under `paymentId`, and `refundIfCharged` uses that reference to issue a refund. It does nothing if no charge exists or the payment has already been refunded. The inventory and shipping services follow the same approach for their own operations.

## Run the workflow

Build a list of those DTOs in execution order:

```typescript
type CheckoutCommand =
  | PaymentCommand
  | InventoryCommand
  | ShippingCommand;

const commands: CheckoutCommand[] = [
  {
    type: 'payment',
    data: {
      paymentId: 'pay-123',
      customerId: 'customer-456',
      amountCents: 4999,
      currency: 'USD',
    },
  },
  {
    type: 'inventory',
    data: {
      reservationId: 'reservation-123',
      items: [{ sku: 'keyboard-01', quantity: 1 }],
    },
  },
  {
    type: 'shipping',
    data: {
      shipmentId: 'shipment-123',
      orderId: 'order-123',
      addressId: 'address-789',
    },
  },
];

try {
  const transaction = await checkout.execute(commands);
  console.log(transaction.status); // COMPLETED
} catch (error) {
  console.error('Checkout failed:', error);
}
```

The example IDs stand in for IDs generated by your application. Each action has its own input; they don't all need an `orderId` or a shared payload. The command union checks those inputs in TypeScript. Sagalicious selects handlers by `type` at runtime; it doesn't validate DTO fields.

If creating the shipment throws, Sagalicious calls the shipping rollback, then inventory, then payment. If compensation succeeds, `execute()` rejects with the original error.

Creating a shipment here means booking it with a provider while it can still be canceled. A parcel that's already been dispatched needs a different recovery process.

One detail matters when writing those handlers: [version 0.1.1](https://www.npmjs.com/package/sagalicious/v/0.1.1) rolls back the entire command list, including commands whose `execute` never ran. That's why the service methods above check whether there's anything to compensate. If payment fails first, the shipping and inventory rollback handlers still run.

A refund is also a new operation, and it can fail. In this version, a rollback error stops the remaining compensations and becomes the error from `execute()`. Keep that behavior in mind when designing recovery for your application.
